# Phase 2.0 — Conversation

> Release 2.0 of Hypernext (codename: Conversation).
> Prerequisites: 1.0 Hypertext, 1.1 Feeds, 1.5 Distributed all shipped.
> Estimated duration: 16 weeks (single maintainer, AI-assisted)
> TDD requirement: Yes — same three layers.

---

## 1. Goal

Add real-time chat across four protocols: IRC, Matrix, XMPP, WebRTC DataChannel. Includes presence, MUC (multi-user chat), MAM (Message Archive Management for history), OMEMO (Matrix and XMPP end-to-end encryption), OTR (off-the-record for IRC).

When 2.0 ships, Hypernext users can:
- Connect to IRC servers, join channels, send/receive messages
- Connect to Matrix servers (with E2EE via Megolm/Olm)
- Connect to XMPP servers (with E2EE via OMEMO)
- Establish WebRTC DataChannel peer-to-peer text chat (for sync release 6.0)
- See a unified chat UI across all protocols with per-protocol badges

This is the largest single release — chat protocols have very different UX from browsing and require persistent connections, presence, and message history.

- [ ] `pub trait ChatSession: Send + Sync`
  ```rust
  #[async_trait::async_trait]
  pub trait ChatSession {
      fn protocol(&self) -> ChatProtocol;
      fn identity(&self) -> &ChatIdentity;
      async fn connect(&mut self) -> Result<(), Error>;
      async fn disconnect(&mut self) -> Result<(), Error>;
      async fn send_message(&self, to: &ChatAddress, msg: &str) -> Result<MessageId, Error>;
      async fn send_typing(&self, to: &ChatAddress) -> Result<(), Error>;
      async fn join_channel(&self, channel: &str) -> Result<(), Error>;
      async fn leave_channel(&self, channel: &str) -> Result<(), Error>;
      async fn fetch_history(&self, channel: &ChatAddress, before: DateTime<Utc>, limit: u32) -> Result<Vec<ChatMessage>, Error>;
      fn events(&self) -> tokio::sync::broadcast::Receiver<ChatEvent>;
  }

  pub enum ChatProtocol { Irc, Matrix, Xmpp, WebRtc }
  pub struct ChatIdentity { protocol: ChatProtocol, address: String, display_name: String }
  pub struct ChatAddress { protocol: ChatProtocol, parts: HashMap<String, String> }
  pub struct ChatMessage { id: MessageId, from: ChatAddress, to: ChatAddress, body: String, timestamp: DateTime<Utc>, encrypted: bool }
  pub enum ChatEvent { MessageReceived(ChatMessage), PresenceChanged(Presence), Typing(ChatAddress), Join(ChatAddress), Leave(ChatAddress), Error(Error) }
  ```

  - `chat_message_fts` (FTS5 over body)
- [ ] Trim messages: keep last 10,000 per channel (configurable); older archived to compressed file

- WebRTC DataChannel API: https://developer.mozilla.org/en-US/docs/Web/API/RTCDataChannel

**Implementation:**

- [ ] `pub struct WebRtcSession { peer_connection: webrtc::peer_connection::RTCPeerConnection, ... }`
- [ ] This is for sync release 6.0 primarily, but text chat over DataChannel is also useful for peer-to-peer without a server
- [ ] Three signaling transports (matching the Wails version's chat-plan.md):
  - **A: Manual SDP blob** — paste the offer/answer manually (works without any infrastructure)
  - **B: Rendezvous endpoint** — POST/GET SDP blobs to a configurable HTTP endpoint

- [ ] DataChannel: text messages as bytes; chunked for >16KB
- [ ] ICE servers: zero default (no STUN/TURN) — user-configurable for NAT traversal
- [ ] Connection state events: `Connecting`, `Connected`, `Disconnected`, `Failed`

## 7. AI-agent instructions for Phase 2.0

**Before writing code:**

1. Read every URL in §6 for the protocol you're implementing.
2. Read `docs/references/library-lookup-protocol.md`.
3. Read `docs/references/0007-keychain-only-secrets.md` — every chat credential goes in keychain.
4. Read the xmpp.rs website in full (https://xmpp.rs/) — the README says "WIP" so verify API stability.

**While writing code:**

1. **ChatSession trait is the contract.** Every protocol implements it; UI never knows what protocol it's rendering.
2. **E2EE is opt-in but encouraged.** Default to encrypted for Matrix; warn (don't block) for unencrypted XMPP.
3. **Auto-reconnect with backoff.** Don't hammer the server if it's down.
4. **Message history is local-first.** Server-side MAM is a fallback for older messages, not the primary store.
5. **WebRTC chat is the foundation for 6.0 sync.** Build it cleanly so sync can reuse it.

**After writing code:**

1. Run `cargo test -p hypernext-chat`.
2. Update `worklog.md`.
3. Conventional Commits: `feat(2.0): add IRC adapter`, `test(2.0): cover Matrix E2EE flow`.
