# Phase 1.2 — Distributed

> Release 1.2 of Hypernext (codename: Distributed).
> Prerequisites: 1.0 Hypertext shipped, 1.1 Feeds shipped.
> Estimated duration: 12 weeks (single maintainer, AI-assisted)
> TDD requirement: Yes — same three layers.

---

## 1. Goal

Add peer-to-peer and write/publish capabilities: IPFS browsing, Iroh data syncing, BitTorrent downloads, remoteStorage, Solid pod access, ATProto publishing, Nostr publishing, Mastodon posting.

When 1.2 ships, Hypernext users can:

- Browse `ipfs://` and `ipns://` URLs
- Pin IPFS content for offline access
- Download via BitTorrent with copyright-warning gate (matching the Wails version's `torrent-plan.md`)
- Connect to remoteStorage and Solid pods, sync files
- Post to ATProto (Bluesky), Nostr, Mastodon — single post or crosspost
- IndieWeb Micropub publish (which was already in 1.0 for the client side, now extended with create/update/delete/reply)

This is the largest release after 1.0 because write paths require consent flows that read paths don't.

### 3.3 remoteStorage (Week 4)

**References to consult:**

- remoteStorage spec: <https://remotestorage.io/spec/>
- remoteStorage OAuth: <https://remotestorage.io/spec/v1.2.2/>
- Original Bean's `internal/remotestorage/` (consult upstream — had full client + sync engine)

**Implementation:**

- [ ] `pub struct RemoteStorageClient { http: reqwest::Client, base_url: Url, token: String }`
- [ ] OAuth 2.0 implicit grant flow:
  - User enters their WebFinger (`user@example.com`)
  - WebFinger lookup → finds remoteStorage `rel` link
  - Redirect to OAuth endpoint with `client_id`, `redirect_uri`, `scope=user_library:rw`
  - Loopback callback (reuse Phase 4's IndieAuth loopback server)
  - Token stored in keychain as `remotestorage.<base_url>`
- [ ] CRUD operations: `GET`, `PUT`, `DELETE` on `<base_url>/<scope>/<path>`
- [ ] ETag-based sync: client tracks last-known ETag per item, server sends `304 Not Modified` if unchanged
- [ ] Conflict detection: server ETag ≠ client ETag → `ConflictError`
- [ ] `pub struct SyncEngine { ... }` — bidirectional sync with conflict classification:
  - `NoConflict` — local and remote both unchanged, or both changed identically
  - `LocalNewer` — local ETag newer, push local to remote
  - `RemoteNewer` — pull remote to local
  - `BothChanged` — manual resolution required (UI presents both versions, user picks)

**TDD gate:**

Unit tests:

- WebFinger lookup returns remoteStorage link → client initialized
- GET existing item → returns content + ETag
- PUT with matching If-Match → success
- PUT with mismatched If-Match → `ConflictError`
- DELETE with matching If-Match → success
- DELETE non-existent → `Error::NotFound`
- Sync: local newer → push to remote
- Sync: remote newer → pull to local
- Sync: both changed → `ConflictError`, both versions returned

Integration tests:

- Mock remoteStorage server (wiremock): full subscribe → sync → resolve-conflict flow
- Token stored in keychain (mocked backend)
- Sync engine: 100 items, half changed → 50 pushed, 50 pulled

## 7. AI-agent instructions for Phase 1.2

**Before writing code:**

1. Read every URL in §6 for the platform you're implementing.
2. Read `docs/references/library-lookup-protocol.md`.
3. Read `docs/references/0007-keychain-only-secrets.md` — every OAuth token goes in keychain.
4. Read Phase 4 §3.7 (IndieAuth) — the loopback server pattern is reused for every OAuth flow here.

**While writing code:**

1. **Explicit confirmation for every write.** Publishing, deleting, uploading — all require user gesture.
2. **Tokens in keychain, never SQLite.** Reuse `hypernext-keychain`.
3. **Crosspost is parallel, not sequential.** Don't serialize; one slow platform shouldn't block others.
4. **Conflict resolution is UI-presented.** Don't auto-resolve `BothChanged` conflicts — show both versions to user.
5. **BitTorrent confirmation is non-bypassable.** If `confirmed=false`, return `Error::ConfirmationRequired`. Never call `start_torrent_download` from navigation.

**After writing code:**

1. Run `cargo test -p hypernext-distributed`.
2. Update `worklog.md`.
3. Conventional Commits: `feat(1.2): add Solid OIDC auth`, `test(1.2): cover DPoP proof generation`.
