# Phase 3.0 — Workshop

> Release 3.0 of Hypernext (codename: Workshop).
> Prerequisites: 1.0-2.0 shipped.
> Estimated duration: 12 weeks (single maintainer, AI-assisted)
> TDD requirement: Yes — same three layers.

---

## 1. Goal

Add terminal sessions, remote file management, MUD/BBS profiles, a built-in LSP-backed editor, and a userscript engine. Hypernext becomes a power-user workstation for the small web — you can SSH into servers, edit files over SFTP, run MUD clients, and write code with LSP autocomplete.

When 3.0 ships, Hypernext users can:

- Transfer files via **FSP** (anonymous UDP file transfer — deferred from Phase 2; uses the `fsp-protocol` crate from merely-made/smolweb)
- Open SSH, Telnet, Telnet/S, Mosh, and Eternal Terminal sessions in a tab
- Connect to FTP/SFTP servers, browse, upload, download, rename, delete files
- Auto-detect ZMODEM transfers in terminal streams and hand off to the download manager
- Use `mud://` and `bbs://` URI schemes (telnet profiles with MUD features: GMCP, MSDP, MCCP)
- Open a built-in code editor (Monaco via embedded webview OR native GTK source view) with LSP support for ~30 languages
- Install userscripts that modify website rendering (GM_* API)

## 5. Risk register

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | `alacritty_terminal` API is not designed for embedding; may need wrapper | Medium | Medium | Spike in week 2; if too hard, use `vte` directly with custom rendering |
| R2 | `libmoshpit` and `etr` are fresh crates; API may be incomplete | High | Medium | Spike each in week 4; fallback to exec system binaries |
| R3 | LSP setup is complex (per-language server, configuration, stdio JSON-RPC) | High | High | Ship v1 editor (GtkSourceView) without LSP; v2 with LSP is opt-in |
| R4 | Userscript `GM_xmlhttpRequest` SSRF surface | High | High | All requests through `FetchPolicy`; `@connect *` forbidden; document risk |
| R5 | Monaco editor in embedded webview may conflict with raw-mode webview usage | Medium | Medium | Use separate webview widget instance per editor tab |
| R6 | SSH host key TOFU doesn't handle key rotation gracefully | Low | Low | Document: user must explicitly accept new key via UI prompt |
| R7 | ZMODEM protocol is underspecified; implementations vary | Medium | Medium | Use real-world captures as fixtures; document deviations |

2. Read `docs/references/library-lookup-protocol.md`.
3. Read `docs/references/0007-keychain-only-secrets.md` — SSH passwords, SFTP passwords go in keychain.
4. Read the original Bean's plans for prior art, but DO NOT copy implementation.

**While writing code:**

1. **SSH host key TOFU is non-bypassable.** Don't disable verification for "convenience."
2. **Userscript SSRF defense is non-bypassable.** `GM_xmlhttpRequest` always goes through `FetchPolicy`.
3. **LSP runs in Restricted Mode by default.** Untrusted dirs don't auto-start LSP servers.
4. **ZMODEM detection must not corrupt the terminal.** When detected, pause rendering immediately.
5. **Terminal emulator widget is shared across SSH/Telnet/Mosh/ET/MUD.** Don't fork the widget per protocol.

**After writing code:**

1. Run `cargo test -p hypernext-workshop`.
2. Update `worklog.md`.
3. Conventional Commits: `feat(3.0): add SSH adapter`, `test(3.0): cover ZMODEM detection`.
