# Phase 5.0 — Confidential

> Release 5.0 of Hypernext (codename: Confidential).
> Prerequisites: 1.0-4.0 shipped.
> Estimated duration: 8 weeks (single maintainer, AI-assisted)
> TDD requirement: Yes — same three layers.

---

## 1. Goal

Add privacy-hardening features: Tor onion routing via Arti, per-tab SOCKS5 webview routing, DNS-over-HTTPS (DoH), a Privacy Shield (uBlock Origin-style static filter lists + Privacy Badger-style heuristic tracker detection + Epic Browser-style anti-fingerprinting), and a Capture consent coordinator for any future capture/indexing features.

When 5.0 ships, Hypernext users can:

- Route all traffic through Tor (Arti as embedded client) with `.onion` URL support
- Configure per-tab SOCKS5 proxies in the embedded webview (so different tabs use different exit nodes)
- Use DoH for all DNS resolution, configurable per-provider
- Block trackers via static filter lists (EasyList, EasyPrivacy) AND heuristic detection (Privacy Badger-style)
- Reduce fingerprinting via canvas/WebGL/audio context randomization in raw-mode webview
- See a unified Privacy panel showing what's blocked, what's allowed, what's fingerprinted

This release is cross-cutting — it layers onto all prior capabilities (chat, mail, news, browsing).

- [ ] Arti doesn't auto-start; user must explicitly enable in settings

### 3.5 Privacy Shield: heuristic tracker detection (Week 5-6)

**References to consult:**

- Privacy Badger algorithm: <https://privacybadger.org/#How-does-Privacy-Badger-work>
- Privacy Badger source: <https://github.com/EFForg/privacybadger>
- Original Bean's `docs/plans/privacy-plan-2.md` (consult upstream — heuristic tracker detection was planned)

**Implementation:**

- [ ] `pub struct HeuristicTrackerDetector { tracking_map: HashMap<Domain, TrackingStats> }`
- [ ] Algorithm (Privacy Badger-style):
  - For each third-party domain (different from page origin), track:
    - Number of requests
    - Cookie presence
    - LocalStorage access
    - Fingerprinting scripts detected (canvas, audio context, WebGL enumeration)
  - If a third-party domain appears on >10 distinct first-party sites AND uses cookies/localStorage/fingerprinting → mark as tracker
  - Once marked: block all requests to that domain
- [ ] Per-site allow/deny overrides: user can whitelist or blacklist specific domains
- [ ] Persistence: `tracker_heuristics` table (domain, first_seen, last_seen, request_count, distinct_first_parties, tracking_methods)
- [ ] UI: Privacy Panel shows detected trackers with their stats and per-domain controls

**TDD gate:**

Unit tests:

- Third-party domain on 1 site → not marked as tracker
- Third-party domain on 11 sites with cookies → marked as tracker
- Whitelist: domain in whitelist → never blocked
- Blacklist: domain in blacklist → always blocked

### 3.6 Privacy Shield: anti-fingerprinting (Week 6) — HIGH RISK

**References to consult:**

- Canvas fingerprinting: <https://en.wikipedia.org/wiki/Canvas_fingerprinting>
- WebGL fingerprinting: <https://en.wikipedia.org/wiki/Device_fingerprint#Canvas_fingerprinting>
- Audio fingerprinting: <https://audiofingerprint.mozilla.org/>
- Tor Browser anti-fingerprinting: <https://torpat.cherv.nodinale.org/>
- Epic Browser: <https://www.epicbrowser.com/>

**Implementation:**

- [ ] In raw-mode webview (Phase 3 §3.4), inject content script that:
  - Wraps `HTMLCanvasElement.prototype.toDataURL`, `toBlob`, `getImageData` — adds deterministic noise to specific pixels
  - Wraps `WebGLRenderingContext.prototype.getParameter` — returns generic values for vendor/renderer strings
  - Wraps `AudioContext.prototype.createOscillator`, `createAnalyser` — adds noise to audio output
  - Wraps `navigator.userAgent`, `navigator.platform`, `navigator.language` — returns Tor Browser values (to blend in)
- [ ] **Noise strategy:** random per-session, but consistent within a session (so canvas rendering still works for legitimate uses)
- [ ] **PII redaction:** user-agent does not include real OS version, real browser version, or anything that could fingerprint the user's actual machine
- [ ] User can disable each category individually in Privacy settings

**TDD gate:**

Unit tests (in webview via `document::eval`):

- `canvas.toDataURL()` returns different value across sessions (deterministic noise)
- `WebGLRenderingContext.getParameter(VENDOR)` returns generic string
- `navigator.userAgent` matches Tor Browser's UA
- `AudioContext.createOscillator()` output has noise
- Legitimate canvas use (draw, then read): within session, same input → same output (consistent noise)

Integration tests:

- Visit <https://amiunique.org> — fingerprint should be uniform with Tor Browser users (manual test; document expected result)

## 5. Risk register

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | Per-tab SOCKS5 in webview is platform-specific and untested in production | High | High | Spike first; fall back to per-window Tor if blocked |
| R2 | Arti embedded client has startup delay (5-10 seconds) | Medium | Low | Show "Connecting to Tor..." spinner; cache consensus documents |
| R3 | Anti-fingerprinting content scripts break legitimate sites | Medium | Medium | Per-site disable toggle; document known-broken sites |
| R4 | Heuristic tracker detection has false positives | Medium | Medium | User whitelist per-domain; ship with conservative threshold (10 sites) |
| R5 | DoH for webview traffic doesn't work cross-platform | Medium | Medium | Document: DoH applies to Rust HTTP traffic; webview uses system DNS (mitigated by Tor if enabled) |
| R6 | Capture consent coordinator has no features to use it yet (no research wiki in 5.0) | High | Low | Ship the coordinator; first consumer is 6.0 sync |

## 7. AI-agent instructions for Phase 5.0

**Before writing code:**

1. Read every URL in §6 for the layer you're working on.
2. Read `docs/references/library-lookup-protocol.md`.
3. Read `docs/references/0007-keychain-only-secrets.md` — Tor client auth keys go in keychain.
4. Read the original Bean's privacy plan — it documents the issues we're trying to avoid.

**While writing code:**

1. **Tor is opt-in only.** Never auto-start Arti; user must explicitly enable.
2. **Anti-fingerprinting is per-category.** Don't apply all categories together without per-category toggles.
3. **Capture consent is non-bypassable.** No feature captures without a consent record.
4. **DoH is opt-in only.** Default off; document the privacy trade-off.
5. **Per-tab SOCKS5 spike FIRST.** Don't write production code until you've verified the webview can do per-tab proxy.

**After writing code:**

1. Run `cargo test -p hypernext-confidential`.
2. Update `worklog.md`.
3. Conventional Commits: `feat(5.0): add Arti Tor client`, `test(5.0): cover anti-fingerprinting`.
