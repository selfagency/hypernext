# Phase 1.1 — Feeds

> Release 1.1 of Hypernext (codename: Feeds).
> Prerequisites: 1.0 Hypertext shipped and stable.
> Estimated duration: 8 weeks (single maintainer, AI-assisted)
> TDD requirement: Yes — same three layers as 1.0.

---

## 1. Goal

Add feed subscription and reading capabilities: RSS, Atom, JSON Feed, Microsub reader, WebSub push, Salmention (mention updates), ActivityPub read-only timelines, AT Protocol read-only timelines, Nostr read-only timelines.

When 1.1 ships, Hypernext becomes a viable feed reader. Users can:
- Subscribe to RSS/Atom/JSON Feed URLs and see them in a feed list
- Receive WebSub push notifications for new entries
- Read ATProto (Bluesky), Nostr, and ActivityPub timelines read-only
- Mark entries as read/unread with a configurable read-delay (default 3 seconds, matching the original PRD S-04)

This release **does not** include write/publishing to any social protocol. That's release 1.5 Distributed.

- Parse RSS 2.0 fixture, Atom fixture, JSON Feed fixture → all produce equivalent `Entry` shape
- FTS5 query "hypernext" returns matching entries

Integration tests:
- `wiremock` server returns RSS with 5 entries → 5 rows in `feed_entries`
- Second fetch with `If-Modified-Since` → 304 → no new entries
- Malformed feed XML → `Error::FeedParse`
- Empty feed (0 entries) → success, 0 rows inserted

### 3.4 WebSub push (Week 4)

**References to consult:**

- WebSub spec (W3C): https://www.w3.org/TR/websub/
- Original Bean's `internal/websub/` (consult upstream)

**Implementation:**

- [ ] `pub struct WebSubListener { http: tokio::net::TcpListener, store: FeedStore }`
  - Binds a TCP port (default 0 = OS-assigned)
  - Handles `GET` (verify intent) and `POST` (push notification) requests
  - Returns 200 OK for verification with `hub.challenge` echoed
  - On POST: parses feed body, calls `FeedFetcher::parse_and_store`
- [ ] For push to work, the listener must be reachable from the internet. v1.1 supports:
  - Localhost only (no remote push) — documented as the default
  - User-configurable port via settings
  - Future: tunnel via Tor onion service (Phase 5) or localtunnel-like service (out of scope)
- [ ] `subscribe_to_hub(feed_url, hub_url) -> Result<(), Error>` — POSTs `hub.mode=subscribe&hub.topic=<feed_url>&hub.callback=<our_callback>`
- [ ] Subscription renewal before lease expiry (default 10 days)

**TDD gate:**

Unit tests:
- WebSubListener starts, accepts GET verification request, returns challenge
- POST push with valid feed body → entries stored
- POST push with malformed body → 400, no entries stored
- Subscription renewal timer fires before lease expires

Integration tests:
- Spin up `wiremock` hub, subscribe to a feed, simulate push POST, verify entries stored
- Verify intent callback works end-to-end

## 5. Risk register

| # | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| R1 | `feed-rs` doesn't parse all feed variants in the wild | Medium | Medium | Capture fixtures from real feeds; contribute fixes upstream |
| R2 | WebSub push doesn't work behind NAT (no public callback URL) | High | Medium | Document as localhost-only in 1.1; Tor onion service callback is 5.0 follow-on |
| R3 | ATProto XRPC API changes between 1.1 dev and release | Low | Medium | Pin `atrium-api` to exact version; test against PDS test instance |
| R4 | Nostr relay diversity causes test flakiness | Medium | Low | Tests use in-process mock relay; production uses user-configured relays |
| R5 | Mastodon API rate-limits public outbox fetches | Medium | Low | Caching: outbox fetched at most every 5 minutes per user |
| R6 | Salmention hooks have no full integration in 1.1 | High | Low | Ship storage + listener; full integration in 1.5 |

## 7. AI-agent instructions for Phase 1.1

**Before writing code:**

1. Read every URL in §6 for the feed type you're implementing.
2. Read `docs/references/library-lookup-protocol.md` — confirm crate versions are current.
3. Read Phase 2 (Protocol trait) and Phase 3 (HTTP reader pipeline) — feed rendering reuses both.

**While writing code:**

1. **Feed subscriptions are stored once.** Re-subscribing to the same URL is idempotent.
2. **WebSub callback is local-only in 1.1.** Don't claim remote push works; document the limitation.
3. **ATProto/Nostr/AP timelines are read-only.** No publish buttons in UI; no token storage in keychain.
4. **Read-state delay is configurable.** Don't hardcode 3 seconds; read from settings.
5. **Test against in-process mock servers.** No test makes real network calls to ATProto/Nostr/AP.

**After writing code:**

1. Run `cargo test -p hypernext-feeds`.
2. Update `worklog.md`.
3. Conventional Commits: `feat(1.1): add RSS subscription`, `test(1.1): cover feed-rs parsing edge cases`.
